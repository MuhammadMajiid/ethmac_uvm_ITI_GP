# ethmac_uvm_ITI_GP
# Ethernet MAC UVM Verification Environment

This repository contains the RTL and SystemVerilog/UVM verification environment for an Ethernet Media Access Controller (MAC). It was developed as an Information Technology Institute (ITI) graduation project.

The project verifies the MAC’s register interface, transmit and receive paths, buffer descriptors, interrupts, and MDIO/MIIM PHY-management interface.

## Project overview

The design under test is a configurable 10/100 Mbps Ethernet MAC featuring:

- Wishbone host and DMA interfaces
- Media Independent Interface (MII) connectivity
- Ethernet frame transmission and reception
- Buffer descriptor management
- CRC generation and checking
- Address filtering
- Flow-control support
- Collision and carrier-sense handling
- Interrupt generation
- MDIO/MIIM PHY management

The verification environment uses UVM components, constrained-random stimulus, scoreboards, a register abstraction layer, functional coverage, RTL code coverage, and automated regressions.

## Verification scope

The environment covers the following areas:

### Register and buffer-descriptor verification

- Register reset values
- Register read and write access
- Read-only and writable field behavior
- Buffer-descriptor access
- Wishbone protocol transactions

### Transmit-path verification

- Basic frame transmission
- Minimum and maximum frame lengths
- Automatic padding
- CRC generation and suppression
- Preamble configuration
- Inter-packet gap configuration
- Buffer-descriptor selection
- Interrupt generation
- Carrier-sense behavior
- Collision handling
- Transmit underrun
- Control and flow-control frames

### Receive-path verification

- Ethernet frame reception
- Frame integrity checking
- Address recognition and filtering
- Receive buffer handling
- Receive-path scoreboarding and coverage

### MIIM verification

- PHY register reads and writes
- Clock-divider configuration
- Preamble handling
- PHY and register address selection
- Continuous scanning
- Scan interrupts
- Command priority
- Back-to-back transactions
- Reset during an active transaction
- Command changes while busy
- Boundary and corner cases

## UVM architecture

The testbench contains reusable agents for the DUT interfaces:

- **Wishbone slave agent (`wb_s`)** — drives host-side register and buffer-descriptor transactions.
- **Wishbone master agent (`wb_m`)** — responds to DMA requests generated by the DUT and models external memory.
- **MII transmit agent (`mii_tx`)** — monitors Ethernet frames transmitted by the MAC.
- **MII receive agent (`mii_rx`)** — drives Ethernet frames into the receive path.
- **MDIO agent** — models the external PHY management interface.
- **Reset agent** — applies controlled hardware reset sequences.

Virtual sequences coordinate activity across the interfaces. TX, RX, and MDIO scoreboards predict expected behavior and compare it against monitored DUT output.

A UVM register abstraction layer models the MAC registers, while coverage collectors measure exercised features, values, and relevant crosses.

## Results and coverage

Generated simulation artifacts are stored below `results/` and grouped by verification area.

Depending on the selected flow, these artifacts include:

- Per-test simulation logs
- Regression summary logs
- Functional coverage databases
- RTL code coverage databases
- Text and HTML coverage reports
- Merged regression coverage databases

The MDIO flow includes documented coverage exclusions in:

```text
scripts/mdio/coverage_exclusions.tcl
```

Each exclusion includes its rationale so that structurally unreachable behavior, known RTL limitations, and untested functionality remain distinguishable.

## Documentation

The `doc/` directory contains supporting project material, including:

Verification-planning spreadsheets contributed by project members are stored under `plan_phase/`.

## Project status

This is an academic verification project. The repository contains generated simulation and coverage results alongside the RTL and verification source code.

Known findings and coverage limitations should be reviewed in the project documentation and regression reports before interpreting the available coverage as full verification closure.
